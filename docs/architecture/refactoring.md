# 도메인 경계 정리

## 범위와 순서

1. 기존 테스트를 기준선으로 실행한다. 관리자 세션 복구, 페이지 삭제, 입력 오류는 테스트를 추가해 잠근다.
2. 공개 서버 설정, 발행 유스케이스, HTTP/정적 응답, Mongo 어댑터를 분리한다. 공개 URL과 응답 계약은 유지한다.
3. 브라우저 assets를 제작기·초대장·발행·저장·분석·미디어·지도 영역으로 옮기고 HTML 로드 순서와 테스트 참조를 함께 갱신한다.
4. 관리자 저장소 권한을 공개 저장소에서 분리하고, 관리자 정적 소스가 Git 추적에서 누락되는 규칙을 수정한다.
5. 실행되지 않는 과거 UI 검증 스크립트, 중복 설계 초안, 낡은 그래프 산출물을 참조 확인 후 제거한다. 사용자 로컬 데이터와 worktree는 보존한다.
6. README 영어/한국어와 현행 아키텍처, Archify 원본을 실제 최종 구조에 맞춘다.
7. 단위/HTTP 테스트, 실제 Mongo 통합, 정적 빌드, 브라우저 제작기·관리자 smoke와 독립 리뷰로 완료를 검증한다.

## 오류 처리 분류

- 관리자 UI의 빈 catch: 실패를 숨기는 처리로 판단해 표시 가능한 오류 상태로 교체한다.
- 발행 재시도/idempotency, IndexedDB 마이그레이션, 외부 지도 fallback: 기존 테스트로 보호되는 호환성 경계이므로 유지한다.
- 관리자 공개 URL의 기본 로컬 주소: 문서화된 개발 기본값으로 유지하되 설정 URL을 검증한다.

이번 정리는 새 프레임워크나 런타임 의존성을 추가하지 않는다. 광범위한 app.js 재작성보다 실행 경계와 파일 책임을 먼저 바로잡는다.
