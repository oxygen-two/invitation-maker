# 위치·지도 기능 분석 보고서 — 구글 맵 연동을 앞두고

작성일: 2026-09-18
대상: `invitation-maker` 대표 장소 / 코스 지도 기능
목적: 해외 사용자를 위한 Google Maps 연동을 시작하기 전에, 현재 네이버 지도 구현의 **애매한 부분**과 **미비한 부분**을 UI/UX 관점에서 짚고, 연동 시 먼저 결정해야 할 것을 정리한다.

이 문서는 코드 읽기 기반의 정적 분석이다. 프로덕션에서 실제 지도가 뜨는지, Google Maps Platform의 현재 요금은 어떤지 같은 항목은 이 문서 안에서 검증하지 못했으며 §9에 "확인 필요"로 별도 표기했다.

---

## 1. 한 줄 요약

현재 지도 기능은 "네이버 하나만 있다"는 전제가 데이터 모델, 입력 UI, 링크 검증, 폴백 링크, 안내 문구, 렌더링 스크립트 전부에 박혀 있다. 구글 맵을 "하나 더 붙이는" 작업이 아니라 **지도 제공자(provider)라는 개념을 처음 만드는** 작업이다. 그리고 구글을 붙이기 전에 이미 아쉬운 UX 문제(좌표를 확인할 방법이 없음, 모바일 스크롤 트랩, 해외 수신자에게 네이버 검색 링크가 열림 등)가 있어, 그것들을 같이 풀어야 해외 사용자가 실제로 쓸 수 있는 기능이 된다.

## 2. 현재 구현 요약 (As-Is)

### 2.1 데이터 모델 (`assets/invitation/core.js`)

| 필드 | 위치 | 비고 |
|---|---|---|
| `naverMapClientId` | 초대장(invitation) 레벨 | `invitation-data.json`의 `site.naverMapClientId`에서 주입. 발행 시 서버로도 전송됨 (`server/validation.cjs` 허용 목록에 포함) |
| `location` | 초대장 | 표시용 장소명 겸 지오코딩 쿼리 |
| `mapUrl` | 초대장 / 코스 아이템 | http(s)면 무엇이든 저장. 단, **좌표 추출은 네이버 호스트만** |
| `mapEnabled` | 초대장 / 코스 | 좌표가 있을 때만 `true`로 정규화 |
| `mapLatitude`, `mapLongitude`, `mapZoom` | 초대장 / 코스 | hidden input. 사용자가 직접 보거나 고칠 수 없음 |

`mapProvider` 같은 필드는 없다. "지도 = 네이버"가 암묵적 전제다.

### 2.2 좌표를 얻는 두 경로 (`assets/integrations/map-location.js`)

1. **지도 링크 우선**: `map.naver.com` 등 6개 네이버 호스트 + `?lat=&lng=` 쿼리가 있을 때만 좌표 인정. place ID 링크, `naver.me` 단축 링크는 "자동으로 확인할 수 없습니다"로 명시 실패.
2. **주소 지오코딩**: 링크가 없으면 `location` 텍스트를 네이버 Geocoder(`submodules=geocoder`)에 보냄. 네이버 지오코더는 **국내 주소 전용**이다.

이 우선순위와 "이름으로 조용히 대체 지오코딩하지 않는다"는 원칙은 `docs/map-url-support.md`에 잘 정리되어 있고 테스트(`tests/map-location.test.js`)로 고정되어 있다. 좋은 설계이며 구글 연동 시에도 유지해야 한다.

### 2.3 지도가 그려지는 세 곳

| 표면 | 로더 | 특이사항 |
|---|---|---|
| 스튜디오 미리보기 iframe | `loadPreviewNaverMaps()` (`app.js`) | 실패 시 "지도 다시 시도" 버튼 |
| 다운로드 standalone HTML | `renderStandaloneMapScript()` (`core.js`) | `file://`이면 즉시 실패 처리. 재시도 없음 |
| 공유 뷰어 `/i/{id}` | standalone HTML을 `srcdoc` + `sandbox` iframe에 주입 | `referrerpolicy="no-referrer"`, `sandbox="allow-scripts allow-popups ..."` (same-origin 없음) |

세 곳 모두 `window.naver.maps.Map` + `Marker` 하나. 인증 실패 훅은 `window.navermap_authFailure` 전역.

### 2.4 폴백(외부 열기) 링크

```
mapUrl 있으면 그대로
없고 장소명 있으면  https://map.naver.com/p/search/{장소명}
없고 지도만 켜져 있으면 https://map.naver.com/
```

즉 **링크를 안 넣은 초대장은 수신자에게 항상 네이버 검색 페이지를 연다.**

### 2.5 문구 (i18n)

편집기 문구는 한/영 사전이 있다. 다만 아래는 언어와 무관하게 네이버를 전제한다.

- 그룹 힌트: `장소 · 네이버 지도` / `Place · NAVER Map`
- 코스 지도 링크 placeholder: `https://map.naver.com/` (사전이 아닌 하드코딩)
- 링크 오류: `올바른 네이버 지도 URL을 입력해 주세요.` (map-location.js 내부 하드코딩, 영어 사전 미적용)
- 서비스 오류: `NAVER Geocoding 설정을 확인해 주세요.` (작성자에게 운영 설정 이름을 노출)
- 검색 실패: `도로명 주소를 입력해 주세요.` / `Try a street address.`

## 3. 애매한 부분 — 구글을 붙이기 전에 결정이 필요한 것

여기 항목들은 "코드가 틀렸다"가 아니라 **답이 정해져 있지 않아서 어느 쪽으로 만들어도 누군가는 불편해지는 지점**이다. 각 항목에 권장안을 적었다.

### A1. "어느 지도를 쓸지"를 누가 정하는가

가능한 기준이 네 가지나 된다.

| 기준 | 장점 | 문제 |
|---|---|---|
| 작성자가 스튜디오에서 명시 선택 | 예측 가능, 단순 | 한국인 작성자가 해외 손님에게 보낼 때 잊기 쉬움 |
| 스튜디오 언어 (ko→네이버, en→구글) | 설정 없이 동작 | 영어 UI로 쓰는 한국 거주자, 한국어 UI로 쓰는 해외 거주 교민이 어긋남 |
| 좌표가 한국 안/밖인지 | 장소 기준이라 가장 정확 | 좌표를 얻기 전엔 판단 불가 (닭과 달걀). 지오코딩 자체가 제공자별로 다름 |
| 수신자의 브라우저 언어/위치 | 수신자 친화적 | 발행된 초대장은 작성자 문서라는 이 프로젝트의 원칙(`shared-invitation.js` 주석)과 충돌 |

**권장**: 작성자 명시 선택을 정답으로 두되, 기본값을 똑똑하게 고른다.
- 기본값 = 스튜디오 언어 기준.
- 좌표를 확보한 뒤 좌표가 한국 밖인데 네이버가 선택되어 있으면 "이 장소는 네이버 지도에서 정확하지 않을 수 있어요. Google 지도로 바꿀까요?" 한 줄 제안(비파괴, 원클릭 전환).
- 수신자 측 자동 전환은 하지 않는다. 대신 §5의 "길찾기 앱 선택" UI로 수신자에게 선택권을 준다.

### A2. 제공자 선택의 단위: 초대장 전체인가, 장소마다인가

코스가 4개 있고 그중 하나가 해외라면? (예: 결혼식은 서울, 신혼여행 첫 모임은 도쿄) 현실적으로 드물지만, 데이터 모델을 초대장 레벨 하나로 잡으면 나중에 되돌리기 어렵다.

**권장**: 필드는 장소 단위(`mapProvider`를 초대장과 코스 아이템 양쪽에)로 두고, UI는 초대장 레벨 선택 하나만 노출한 뒤 코스는 그 값을 상속한다. 코스별 오버라이드 UI는 1차 범위에서 제외한다.

### A3. 구글 링크 중 무엇을 "신뢰할 수 있는 좌표"로 볼 것인가

현재 문서가 세운 원칙 "카메라 중심은 마커가 아니다"를 구글 URL에 그대로 적용하면 다음처럼 갈린다.

| 구글 URL 형태 | 좌표 성격 | 권장 처리 |
|---|---|---|
| `google.com/maps/place/이름/@37.57,126.99,17z/data=...!3d37.5741!4d126.9916...` | `@`는 카메라 중심, `!3d`/`!4d`는 실제 장소 좌표 | `!3d!4d` 있으면 그것을 신뢰. 없고 `@`만 있으면 "위치 확인 필요" 상태로 넣고 사용자에게 지도 위에서 확인 요청 |
| `google.com/maps?q=37.57,126.99` 또는 `maps/search/?api=1&query=37.57,126.99` | 명시 좌표 | 신뢰 |
| `google.com/maps?q=장소명` | 텍스트 검색 | 지오코딩 대상 (링크 그대로 폴백 링크로도 사용) |
| `maps.app.goo.gl/xxxx`, `goo.gl/maps/xxxx` | 단축 링크, 리다이렉트 | 브라우저에서 CORS로 풀 수 없음. **서버 리졸버 없으면 네이버 `naver.me`와 같은 "자동 확인 불가" 처리** |
| `maps.google.com/?cid=...`, `place_id` | 장소 ID | Places API 필요. 1차 범위 제외 |

**권장**: 1차에서는 명시 좌표(`q=`, `query=`, `!3d!4d`)만 신뢰하고, 그 외는 네이버 place 링크와 동일하게 "외부 열기 버튼은 유지, 자동 위치는 불가" 메시지를 낸다. 실제 해외 사용자가 가장 많이 붙여넣는 것은 모바일 공유로 나오는 `maps.app.goo.gl` 단축 링크이므로, **단축 링크 서버 리졸버는 2차 우선순위로 명확히 남긴다.**

### A4. 주소 지오코딩은 어느 제공자로 하는가

- 네이버 지오코더는 국내 주소만 돌려준다. 해외 주소를 넣으면 `NOT_FOUND` → "도로명 주소를 입력해 주세요"라는, 해외 사용자에게는 오해를 주는 문구가 나온다.
- 구글 Geocoding은 전 세계를 다루지만 국내 상호명("살롱순라 서순라길점")의 인식률은 네이버가 낫다.

**권장**: 지오코딩 제공자 = 선택된 지도 제공자. 교차 사용(네이버 지도에 구글 좌표)은 좌표계(WGS84)가 같아 기술적으로 가능하지만 사용자 멘탈 모델을 흐리므로 하지 않는다. 대신 A1의 "제공자 바꿀까요?" 제안으로 해결한다.

### A5. 수신자에게 열어줄 "외부 지도" 링크

현재 `getMapFallbackUrl`은 무조건 네이버다. 해외 수신자는 네이버 계정도 앱도 없고, 네이버 지도 웹은 영어 UI가 제한적이다. 반대로 국내 수신자는 카카오맵/네이버가 있어야 편하다.

**권장**: 링크 하나가 아니라 **좌표 기반 다중 앱 열기**로 설계한다 (§5.4). 좌표가 없고 텍스트만 있을 때의 폴백은 제공자별로 갈라야 한다.

```
naver  : https://map.naver.com/p/search/{q}
google : https://www.google.com/maps/search/?api=1&query={q}
```

### A6. 발행된 초대장의 chrome 언어

`shared-invitation.js`는 발행 초대장 안쪽 chrome(지도 버튼 문구 "대표 지도 열기")을 **항상 한국어**로 그린다. 저장 문서에 언어가 없기 때문이다. 해외 사용자를 대상으로 하려면 구글 맵과 별개로 이 결정을 다시 열어야 한다. 지도 버튼이 한국어면 지도가 구글이어도 해외 수신자는 버튼을 못 찾는다.

**권장**: 발행 payload에 `language`를 추가 (`server/validation.cjs` 허용 목록 + 기본값 `ko`). 지도 제공자 필드를 추가하는 김에 같은 마이그레이션으로 처리하는 것이 비용이 가장 낮다.

### A7. 중국 등 좌표계 변위 지역

Google은 중국 본토 지도를 GCJ-02로 표시하고, 좌표 입력은 WGS84로 받는다. 상하이 장소에 마커가 수백 m 어긋나는 문제는 유명하다. 이 제품의 1차 해외 타깃이 어디인지에 따라 무시할 수도, 경고 문구가 필요할 수도 있다. **결정 필요.**

## 4. 미비한 부분 — 구글이 없어도 지금 이미 아쉬운 것

심각도: **높음** = 사용자가 잘못된 결과를 눈치 못 채거나 기능을 포기하게 됨, **중간** = 불편하지만 우회 가능, **낮음** = 다듬기.

### G1. [높음] 확인된 좌표가 "어디"인지 알려주지 않는다

지오코딩 성공 시 메시지는 "지도 위치를 확인했습니다."뿐이다. 어떤 주소로 해석했는지, 몇 번째 후보인지 표시하지 않으며 `coordinatesFrom`은 첫 번째 결과만 쓴다. 미리보기 지도가 유일한 확인 수단인데, 미리보기는 별도 패널이고 모바일에서는 스크롤로 한참 아래에 있다 (스크롤 자동 이동 `revealPendingPreviewMap`이 있긴 하다).

같은 이름의 지점이 여러 개인 상호("스타벅스 성수")를 넣으면 엉뚱한 지점이 조용히 찍힐 수 있다. 구글로 가면 후보가 전 세계로 늘어나 이 문제가 더 커진다.

→ §5.2 "위치 확인 카드" 참고.

### G2. [높음] 좌표를 손으로 고칠 방법이 없다

`mapLatitude/Longitude/Zoom`이 hidden input이다. 마커 드래그, 줌 조정, 좌표 직접 입력 중 어느 것도 없다. 지오코딩이 틀렸을 때 사용자가 할 수 있는 건 주소를 바꿔 넣는 것뿐이다. 신축 건물, 이름이 바뀐 가게, 해외 시골 주소에서 특히 문제다.

### G3. [높음] 모바일에서 지도가 스크롤을 삼킨다 (스크롤 트랩)

`new maps.Map(canvas, { center, zoom })` 옵션만 주고 있어 네이버 기본값(드래그·스크롤휠·핀치 모두 활성)이 적용된다. 초대장은 세로 스크롤 문서이고 지도는 260px(모바일 220px) 높이 패널이 대표 1개 + 코스마다 1개씩 들어갈 수 있다. 손가락이 지도 위에 닿으면 페이지가 안 내려가고 지도가 움직인다. 코스 4개에 모두 지도를 켜면 화면의 절반 이상이 스크롤 트랩이 된다.

구글 Maps JS API에는 `gestureHandling: "cooperative"`(두 손가락으로만 이동)가 있고, 네이버도 `scrollWheel`, `draggable`, `pinchZoom` 옵션을 끌 수 있다. 두 제공자 모두에 대해 **"초대장 안 지도는 기본 잠금, 탭하면 활성화"** 규칙을 정하는 것이 좋다.

### G4. [높음, 확인 필요] 공유 뷰어의 sandbox·no-referrer가 지도 SDK 인증을 막을 가능성

`shared-invitation.js:83-85`는 초대장을 `srcdoc` + `sandbox`(same-origin 없음, 즉 opaque origin) + `referrerpolicy="no-referrer"` iframe에 넣는다. 네이버 Maps API는 등록된 "Web 서비스 URL"을 Referer로 검사한다. Referer가 없으면 인증 실패 → `navermap_authFailure` → "지도를 불러올 수 없습니다"가 될 수 있다. `docs/map-url-support.md`도 "production SDK/domain validation remains separate"라고 적어 두었고, `scripts/verify-map-url.cjs`는 `maps.js`를 일부러 abort하므로 **자동 검증이 이 경로를 한 번도 실제로 밟지 않는다.**

Google Maps JS API 키도 "HTTP referrer" 제한을 거는 것이 표준인데, 같은 이유로 sandbox iframe 안에서 거부될 수 있다. 제한 없는 키를 쓰면 키 도용 위험이 생긴다. 즉 **이 구조적 문제를 풀지 않으면 구글도 같은 자리에서 막힌다.**

해결 후보: (a) iframe에 `allow-same-origin`을 주고 referrer 정책을 `strict-origin`으로 완화 (초대장 ID가 path에 있으므로 origin만 보내면 개인정보 문제 없음), (b) 지도를 sandbox 밖 부모 문서에서 렌더링, (c) Static Map 이미지로 대체(§6). 프로덕션에서 먼저 사실 확인이 필요하다 (§9).

### G5. [중간] 해외 수신자에게 열리는 것은 네이버 검색 페이지

§2.4 참조. 링크를 넣지 않은 초대장의 "대표 지도 열기"는 `map.naver.com/p/search/{장소명}`이다. 영어 장소명을 네이버에서 검색하면 결과가 없거나 국내 결과가 나온다.

### G6. [중간] 지도 링크 입력이 네이버 링크만 받아준다

구글 링크를 붙여넣으면 "네이버 지도 URL을 입력해 주세요"라는 오류가 나오고 좌표가 비워진다. 그런데 `normalizeMapUrl`은 어떤 http(s) URL이든 저장하므로 **초대장에는 구글 링크 버튼이 정상적으로 들어간다.** 즉 사용자는 "오류"라는 말을 듣지만 실제로는 절반은 동작하는, 상태가 어긋난 경험을 하게 된다. 이 오류 문구는 `map-location.js`에 한국어로 하드코딩되어 있어 영어 UI에서도 한국어로 뜬다.

### G7. [중간] 용어와 체크박스 흐름이 어렵다

- "대표 동적 지도 표시"(ko) / "Show a live map for this place"(en). "동적"은 개발자 용어다. 사용자는 "지도를 넣을지 말지"만 궁금하다.
- 체크박스를 켜야만 지오코딩이 시작되고, 링크만 넣으면 지도는 안 나오고 버튼만 나온다. 이 두 결과(지도 패널 vs 버튼)의 차이를 UI가 설명하지 않는다. 스크린샷(`docs/ui-ux-global-audit/2026-09-18/screenshots/05-location-naver-map.jpg`)을 보면 "Map link" 입력칸이 무엇을 위한 것인지 도움말이 없다.
- 그룹 힌트에 "네이버 지도"라고 써 두어, 구글을 쓰고 싶은 사용자는 여기서 이미 이 제품이 자기용이 아니라고 느낀다.

### G8. [중간] 다운로드 HTML의 지도는 항상 실패 상태로 시작한다

standalone 스크립트는 `location.protocol === "file:"`이면 바로 "지도를 불러올 수 없습니다"를 띄운다. 다운로드한 사람이 파일을 더블클릭해서 열면 지도 자리에 오류 문구가 보인다. 오류가 아니라 "이 파일을 웹에 올리면 지도가 표시됩니다" 같은 정보성 문구여야 하고, 가능하면 정적 이미지가 대신 보여야 한다. Google Static Maps 또는 네이버 Static Map 이미지를 기본 레이어로 두고 SDK가 성공하면 위에 얹는 **점진적 향상** 구조가 두 제공자 모두에 맞다.

### G9. [중간] API 키가 공개 데이터에 있고 발행 payload에도 들어간다

`invitation-data.json`의 `site.naverMapClientId`는 공개 파일이며 `naverMapClientId`는 발행 시 서버로 전송되어 문서에 저장된다. 네이버 클라이언트 ID는 도메인 제한이 있어 노출이 치명적이진 않지만, 구글 키는 referrer 제한이 없으면 과금 도용 대상이 된다. 또한 키가 초대장 문서에 저장되는 구조는 **키를 교체(rotate)하면 이미 발행된 초대장이 옛 키로 남는다**는 뜻이다. 사이트 설정(런타임 주입)과 문서 데이터를 분리해야 한다.

### G10. [중간] 접근성

- 지도 canvas에 대체 텍스트가 없다. `aria-label="약속 장소 지도"`는 섹션에만 있다.
- 지도 근처에 주소 텍스트가 없다. 스크린리더 사용자, 지도가 실패한 사용자 모두 주소를 다른 섹션에서 찾아야 한다.
- 초대장 안 "장소 지도 열기" 링크는 최소 높이 44px로 잘 잡혀 있다 (좋음).

### G11. [낮음] 분석·검증 공백

- 분석 이벤트는 `has_map` boolean 하나. 제공자별 사용률, 링크 붙여넣기 vs 주소 입력 비율, 지오코딩 실패율을 알 수 없어 구글 도입 후 효과를 측정할 수 없다. (좌표·주소를 보내지 않는 현재 정책은 유지해야 한다.)
- `tests/map-location.test.js`는 네이버 URL만 다룬다. `verify-map-url.cjs`는 SDK 로드를 차단한다. 실제 지도 렌더는 사람 손으로만 확인된다.

### G12. [낮음] 개인정보 고지

Google Maps 임베드/JS API는 로드 시 구글 쿠키를 세팅한다. 해외(특히 EU) 수신자를 타깃하면 동의 배너 없이 지도를 자동 로드하는 것이 GDPR 이슈가 될 수 있다. "지도 보기" 탭 이후에만 로드하는 방식(§5.3)이 UX 문제(G3)와 개인정보 문제를 동시에 푼다.

## 5. 제안 UX 설계

### 5.1 편집기 "대표 장소" 그룹 (제안)

```
┌ 대표 장소 ───────────────────────────── 장소 · 지도 ─┐
│ 지도 서비스    [ 네이버 ] [ Google ]                  │  ← 세그먼트, 기본값은 스튜디오 언어
│                                                       │
│ 장소 또는 주소  [ 살롱순라 서순라길점            🔍 ] │  ← 제공자별 자동완성
│                                                       │
│ ▸ 지도 링크 붙여넣기 (선택)                            │  ← 접힘. 열면 어떤 링크가 되는지 한 줄 안내
│                                                       │
│ [✓] 초대장에 지도 넣기                                 │  ← "동적" 제거
│ ┌───────────────────────────────────────────────┐    │
│ │ ✓ 서울 종로구 율곡로10길 75   [지도에서 위치 확인] │    │  ← 위치 확인 카드 (5.2)
│ │   위치가 다르면 마커를 끌어 옮기세요.            │    │
│ └───────────────────────────────────────────────┘    │
└───────────────────────────────────────────────────────┘
```

핵심 변화 세 가지:
1. **제공자 선택이 맨 위.** 아래 모든 입력의 의미(자동완성 대상, 링크 허용 호스트, 오류 문구)가 이 선택에 따라 바뀐다.
2. **자동완성 검색.** 해외 사용자에게 "도로명 주소를 입력하세요"는 통하지 않는다. Google Places Autocomplete(또는 네이버 검색 API)가 주소 형식 부담을 없앤다. 이 한 가지가 해외 사용성의 대부분을 결정한다.
3. **링크 붙여넣기는 보조 수단으로 접기.** 지금은 링크 칸이 주소 칸 옆에 같은 무게로 있어 "둘 다 넣어야 하나?"라는 혼란을 준다.

### 5.2 위치 확인 카드

지오코딩/링크 해석 결과를 다음 세 상태로 보여준다.

| 상태 | 표시 | 행동 |
|---|---|---|
| 확인됨 | 해석된 정규 주소 + 작은 정적 지도 썸네일 | "지도에서 위치 확인" → 미리보기 스크롤 or 인라인 미니맵 |
| 확인 필요 | "카메라 위치만 있는 링크예요" / "후보가 여러 개예요" + 후보 목록 | 후보 선택, 마커 드래그 |
| 실패 | 제공자별 문구 (네이버: "국내 주소만 찾을 수 있어요. 해외 장소면 Google로 바꿔 보세요.") | 제공자 전환 원클릭 |

G1·G2·A3를 한 컴포넌트로 해결한다.

### 5.3 초대장 안 지도 패널 (수신자 화면)

- 기본은 **정적 지도 이미지 + 마커** (Static Map). 로드가 빠르고 스크롤을 삼키지 않으며 `file://`에서도 이미지 URL이면 보인다(네트워크만 있으면).
- 이미지 위에 "지도 움직이기" 또는 탭 오버레이. 탭하면 그때 SDK를 로드해 인터랙티브 지도로 교체. G3(스크롤 트랩), G8(다운로드 파일), G12(쿠키 동의) 모두 완화된다.
- 지도 아래에 주소 텍스트를 항상 출력 (G10).
- SDK 실패 시 정적 이미지가 남아 있으므로 "불러올 수 없습니다"라는 빈 상자를 보여줄 일이 줄어든다.

### 5.4 "길찾기" 버튼: 링크 하나가 아니라 앱 선택

좌표가 있으면 링크를 생성할 수 있는 앱이 여럿이다.

| 앱 | URL 형식 (좌표 기반) | 대상 |
|---|---|---|
| 네이버 지도 | `nmap://place?lat=&lng=&name=` (앱) / 웹 폴백 | 국내 |
| 카카오맵 | `https://map.kakao.com/link/to/{name},{lat},{lng}` | 국내 |
| Google Maps | `https://www.google.com/maps/dir/?api=1&destination={lat},{lng}` | 전 세계 |
| Apple Maps | `https://maps.apple.com/?daddr={lat},{lng}&q={name}` | iOS 해외 |

제공자가 네이버면 [네이버·카카오·Google], 구글이면 [Google·Apple]을 기본 세트로 노출한다. 작성자가 넣은 `mapUrl`이 있으면 그 제공자의 항목이 원본 링크를 쓴다. 이 버튼 시트는 좌표만 있으면 되므로 **SDK 없이도 동작**하는, 가장 저렴하고 가장 효과 큰 해외 대응이다.

### 5.5 문구 원칙

- 제공자 이름은 사전 키로 치환: `map.provider.naver`, `map.provider.google`. 힌트 "장소 · 네이버 지도" → "장소 · 지도".
- 오류 문구에서 운영 설정 이름(NCP, Geocoding, API key)을 없앤다. 작성자에게는 "지금 위치 검색이 안 돼요. 잠시 후 다시 시도하거나 지도 링크를 붙여넣어 주세요."로 충분하고, 설정 오류는 `reportFault`로 운영자에게 간다 (이미 그렇게 되어 있다).
- `map-location.js` 안의 한국어 하드코딩 메시지는 코드 → 사전 키로 옮긴다.

## 6. 구글 맵 연동 방식 비교

| 방식 | 키 | 좌표 확보 | 커스터마이징 | sandbox iframe 호환 | 비용 성격 | 적합한 용도 |
|---|---|---|---|---|---|---|
| 링크만 (Maps URLs) | 불필요 | 없음 (텍스트 검색) | 없음 | 문제 없음 | 무료 | 길찾기 버튼 (5.4). **1단계** |
| Maps Embed API (iframe) | 필요 | 없음 (place/q 파라미터) | 마커·줌 정도 | 중첩 iframe으로 동작 예상, referrer 제한은 동일 이슈 | 무료 (공식 정책 재확인) | 가장 싼 "지도 패널" |
| Maps Static API (이미지) | 필요 | 좌표 필요 | 마커·스타일 | 이미지라 문제 없음 | SKU별 월 무료 한도 | 5.3의 기본 레이어, 다운로드 파일 |
| Maps JavaScript API | 필요 | Geocoder / Places 포함 | 최대 | G4와 동일한 referrer 이슈 | SKU별 월 무료 한도 후 과금 | 인터랙티브 지도, 자동완성 |
| Geocoding / Places API | 필요 | **이것이 핵심** | - | 서버 프록시 권장 | 호출당 과금(무료 한도 있음) | 5.1 자동완성, 5.2 확인 카드 |

**권장 순서**
1. **길찾기 앱 선택 시트 + 폴백 링크 제공자 분기** (키 없음, 위험 없음, 해외 수신자 체감 큼).
2. **`mapProvider` 필드 + 구글 링크 좌표 파서 + 문구 정리** (프론트만, 정적 테스트 가능).
3. **Static Map 기본 레이어 + 탭하여 활성화** (두 제공자 공통, G3/G8/G12 해결).
4. **Places Autocomplete + 위치 확인 카드** (해외 작성자 UX의 본체. 키 관리와 과금 설계 필요).
5. 단축 링크 서버 리졸버 (`maps.app.goo.gl`, `naver.me`), 코스별 제공자 오버라이드.

요금: Google Maps Platform은 2025년 3월에 월 $200 크레딧 방식에서 **SKU별 월 무료 호출량** 방식으로 바뀐 것으로 알고 있다. 정확한 한도와 Embed API 무료 여부는 도입 시점에 공식 요금 페이지에서 다시 확인해야 한다 (§9).
