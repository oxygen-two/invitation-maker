# 익명 초대장 발행

사용자 승인: 로그인 없이 Node.js + MongoDB에 Base64 이미지를 포함해 발행한다. R2·로그인·개별 OG·제작기 모듈 분리는 이번 범위에서 제외한다. 기존 HTML/CSS/JS 제작기·로컬 보관함·다운로드를 유지한다.

## 계약

- POST /api/invitations: JSON `{invitation}`. UTF-8 요청 본문과 정규화된 초대장 각각 최대 2,000,000 bytes. 헤더 `Authorization: Bearer <32-byte base64url token>`과 `Idempotency-Key: <UUID>`는 브라우저가 생성하고 요청 전에 로컬 보관한다. 성공 `{id,url:'/i/<id>',expiresAt:null|string}`. 동일 키·토큰·내용의 재시도는 같은 링크, 다른 내용은 409.
- GET /api/invitations/:id: `{invitation,expiresAt}`만 반환. 관리 해시·IP·멱등 키는 공개하지 않는다.
- DELETE /api/invitations/:id: 관리 토큰 검증 후 삭제, 성공 204. 토큰 없는 요청은 거부한다.
- 공유 ID는 암호학적 무작위 Base62 22자리. 관리 토큰과 독립적이다.
- /i/:id는 공개 뷰어. 별도 브라우저에서도 API로 읽고 기존 렌더러로 생성한 초대장을 sandbox iframe에 표시한다. API는 no-store, noindex, no-referrer를 사용한다.
- 초안 변경은 발행 스냅샷에 반영하지 않는다. 첫 버전은 새 링크 발행 및 기존 링크 취소만 제공한다.

## 저장·만료·비용 제한

- MongoDB 컬렉션에 JSON과 Base64를 함께 저장한다. raw HTML 업로드 발행은 제공하지 않는다.
- TTL은 미확정이므로 `PUBLISH_TTL_DAYS=0`을 명시적 기본으로 두고 UI에 자동 만료 없음으로 표시한다. 양수 설정이면 서버 시각으로 expiresAt을 계산한다. 이는 영구 보존 약속이 아니다.
- 서버는 GET에서 expiresAt을 검사한다. Mongo TTL 삭제는 비동기이므로 접근 허용 판단으로 사용하지 않는다.
- 기본 IP당 시간당 10회, 서비스 전체 하루 100회, 누적 1,000회 발행 제한. 모두 서버 환경변수로 조정한다. 누적 한도는 삭제·만료 시 자동 복구하지 않는 보수적 비용 상한이다. 저장 실패·중복 경합 시 누적 예약은 반환한다.
- IP는 신뢰할 프록시를 명시한 환경에서만 전달 헤더를 사용한다. Mongo 원자 연산으로 여러 프로세스 간 한도를 유지한다. 제한 실패는 429/503으로 표시한다.
- 허용하는 데이터 타입·문자열 길이·항목 수·이미지 MIME/바이트 시그니처·크기를 서버에서 검사하고 기존 normalizeInvitation을 적용한다. 클라이언트 검증을 신뢰하지 않는다.
- MongoDB URI와 DB명은 서버 환경변수에만 둔다. 자격 증명이 없으면 발행은 명시적 503이며 메모리 저장으로 대체하지 않는다.

## UI

완료 화면에 공유 링크 만들기, 크기/공개 안내, 발행 상태, 링크 복사, 이 브라우저의 발행 목록·취소를 추가한다. 관리 토큰은 발행 전에 저장해야 하며 저장 불가 시 발행하지 않는다. 응답 유실은 저장된 요청을 재시도한다. 공개 URL에 관리 토큰을 넣지 않는다. 관리 토큰은 분석 이벤트로 보내지 않는다.

## 실행 및 검증

Node >=22와 공식 mongodb 드라이버만 추가한다. Node 서버는 정해진 공개 파일만 제공한다. Vercel용 API 어댑터는 동일 핸들러를 사용한다. MongoDB 접속은 제공된 Atlas 호스트만으로 불가능하므로 운영 인증 연결은 미검증으로 남긴다. 격리된 로컬 MongoDB로 실제 저장·재시작·동시 한도·만료·삭제를 검증한다. 브라우저는 두 컨텍스트로 발행/수신, 사진, 320/390/768/1440px, 실패/복사/취소를 검사한다. 기존 테스트 264개 기준선을 보존한다.

## 추가 요청: GA4 방문 집계 준비

사용자는 방문자 수를 확인할 Google Analytics 연결을 추가 요청했다. 기존 Vercel/PostHog 구성을 보존하고 GA4는 측정 ID가 있을 때만 동작하는 별도 선택 모듈로 추가한다. 측정 ID는 아직 제공되지 않았으므로 기본 비활성이다. 운영 호스트·사용자 추적 거부 설정을 존중하며, 제목·주소·사진·공유 식별자·관리 키·원문 쿼리/리퍼러를 분석 이벤트에 포함하지 않는다. GA4 속성 생성이나 실제 수집 완료는 계정/측정 ID 없이 주장하지 않는다.
